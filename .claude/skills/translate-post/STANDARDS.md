# 翻译标准

三条总标准，按优先级排：**准确 > 像中文原创 > 保留作者风格**。冲突时前者优先；但"准确"指意思准确，不是逐词对应。

## 1. 意思准确

- 不增不减：每个论点、例子、限定词（"often""may""in our experience"）都要有对应。拿不准的句子宁可多想，不要含糊带过。
- 数字、单位、日期、百分比、产品名、版本号原样保留，逐个核对。
- 原文的链接全部保留，挂在对应的中文词上；脚注改成 Markdown 脚注 `[^1]`。
- 代码、命令、工具名、参数名、枚举值、路径保持英文原样，放在反引号里。
- 原文有意为之的强调（斜体、加粗、引号）在译文里用加粗或引号保留。

## 2. 像中文原创

读起来要像一位懂行的中文作者自己写的技术文章，而不是"翻译腔"。

- 拆长句：英文一句挂三个从句的，拆成两三句短句，按中文的逻辑顺序（先原因后结果、先条件后结论）重排。
- 动词优先：把"进行……的优化""对……做出评估"还原成"优化""评估"；少用"被"字句，能改主动就改主动。
- "的"字不连用超过两个；"一个""一种"能省就省。
- 用中文全角标点；中文和英文、数字之间加一个空格（`LLM 智能体`、`25,000 个 token`）。
- 小标题译成中文读者一眼能懂的说法，可以意译，不必死扣原词。
- 习语、比喻找中文里对等的说法；找不到就直译并保留意象，必要时在译者注里解释。

## 3. 保留作者风格

- 人称跟原文走：原文用"we"就写"我们"，用"I"就写"我"，用"you"就写"你"。
- 语气跟原文走：口语化的写得口语化，严肃的写得严肃；原文的幽默、自嘲、双关尽量保住，保不住的在译者注里说明。
- 段落一一对应，不合并、不删减、不调换顺序；列表、小标题层级与原文一致。
- 作者反复使用的关键词，全文用同一个中文译法。

## 术语

- 本站已有的译法优先，保持全站一致：先 `grep -A30 '^## 译者注' _posts/*.md` 看前几篇怎么译的（例如 agent → 智能体）。
- 新术语首次出现写作"中文（English）"，之后只用中文。
- 业内普遍不译、或中文译法会丢意思的词（如 harness），保留英文，并在译者注里说明理由。
- 每个有取舍的术语都记进文末"译者注"。
